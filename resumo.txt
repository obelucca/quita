Resumo da Implementação - Plataforma Quita

1. SDD-0001 - Cadastro de Usuário (Register)
   - Criada a infraestrutura do banco de dados (tabela 'users', Flyway migrations V1 e V2).
   - Implementado o fluxo de cadastro via POST `/auth/register` com validação de dados de entrada.
   - Criptografia de senhas com BCrypt.
   - Tratamento global de exceções (incluindo tratamento para email duplicado com status 409).

2. SDD-0002 - Autenticação JWT (Login)
   - Adicionada dependência da biblioteca JJWT (Java JWT v0.12.7) no pom.xml.
   - Criada classe `JwtService` para geração, extração e validação de tokens JWT.
   - Implementada autenticação em modo STATELESS com Spring Security 7.
   - Criado filtro `JwtAuthenticationFilter` interceptando as requisições privadas com Bearer Token.
   - Exposto endpoint POST `/auth/login` gerando tokens JWT válidos após validação de credenciais.
   - Tratamento de credenciais inválidas e usuário não encontrado com status 401 Unauthorized.

3. SDD-0003 - Upload de Relatório Registrato
   - Criada tabela `documents` via Flyway migration V3 com chave estrangeira apontando para a tabela `users`.
   - Criados modelo JPA `Document`, enum `DocumentStatus` (UPLOADED, PROCESSING, PROCESSED, FAILED) e repository.
   - Criada camada de armazenamento local `LocalStorageService` que salva os uploads na pasta local configurada.
   - Implementada validação no `DocumentService` (tamanho limite de 20MB e formatos permitidos de arquivo, aceitando apenas PDFs).
   - Exposto endpoint POST `/documents/upload` que aceita MultipartFile e associa o documento ao usuário autenticado.
   - Exposto endpoint GET `/documents` que retorna a lista de documentos do usuário autenticado no contexto de segurança.
   - Implementado tratamento global para exceções de tipo inválido (400 Bad Request) e arquivo muito grande (413 Payload Too Large).

4. Testes e Validação
   - Atualizada a suíte de testes de integração (`AuthControllerTest`, `JwtServiceTest` e `DocumentControllerTest`).
   - Implementados testes específicos para cobrir upload de PDF com sucesso, recusa de extensões não permitidas, bloqueio de arquivos muito grandes (> 20MB), multi-tenant isolation (garantindo que um usuário não liste documentos de outros) e bloqueio de requisições sem autenticação.
   - Limpeza de banco de dados ajustada nas suítes de testes usando `deleteAllInBatch()` para evitar conflitos de dados persistidos.
   - Todos os 17 testes automatizados da API estão passando com sucesso no build Maven.
